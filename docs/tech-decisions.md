# 技術決策說明（為什麼這樣做）

> 用白話記錄本專案每個重要技術決策的「為什麼」，讓非本專案的開發者也能快速理解取捨。
> 格式：一句話答案 → 白話比喻 → 延伸問題。

---

## 1. 為什麼訂單扣庫存要用「交易＋行級鎖」（lockForUpdate）？

**一句話**：防止兩個人同時下單把同一件庫存賣出去兩次（超賣）。

**比喻**：便利店最後一個便當，兩個客人同時伸手。行級鎖就是店員先把便當拿到櫃檯（鎖住這一列資料），第一個人結完帳，第二個人才能看庫存——這時已經是 0，訂單就會被擋下。

**延伸：什麼是交易（Transaction）？**：把「建訂單＋扣庫存＋寫明細」包成一組，要嘛全部成功，要嘛全部取消，不會出現「訂單建了但庫存沒扣」的半套狀態。

**延伸：鎖整張表不行嗎？**：行級鎖只鎖「這筆商品」，別的商品照常下單；鎖整張表會讓所有人排隊，效能差很多。

## 2. 為什麼訂單明細要存「價格快照」而不是關聯商品現價？

**一句話**：訂單是歷史事實，商品之後漲價不能改變當初成交的金額。

**比喻**：發票印出來就定案了，之後菜單漲價，發票不會跟著變。

**延伸**：`order_items` 存下單當下的 `price`，之後對帳、報表、退貨都以快照為準。

## 3. 為什麼訂單狀態要用「狀態機」（canTransitionTo）？

**一句話**：狀態只能照合法路線走（待處理→處理中→已出貨→已完成），防止「已取消的訂單被出貨」這種怪事。

**比喻**：捷運路線圖——車只能開到相鄰的下一站，不能從動物園直接跳到淡水。

**延伸：取消訂單怎麼處理庫存？**：取消時把品項數量加回庫存（還貨），一樣包在交易裡。

## 4. 為什麼 User 的 role（角色）欄位不放進 fillable？

**一句話**：防止有人在註冊表單偷塞 `role=admin` 把自己變管理員（Mass Assignment 攻擊）。

**比喻**：報名表上沒有「職位」欄位可以填，職位只能由人資（程式裡明確指定）發派。

**延伸**：權限判斷用 Laravel Policy 集中管理，Blade 用 `@can` 控制按鈕顯示，Controller 用 authorize 擋非法請求——前後端都要擋，前端只是體驗，後端才是防線。

## 5. 為什麼 API 用 Sanctum 而不是 session？

**一句話**：API 的使用者是程式（POS 機、手機 App），不是瀏覽器，用 token（一組長密碼字串）帶在每個請求上驗證身分比較合適。

**比喻**：session 像進公司刷的員工證（綁瀏覽器），token 像活動手環——發給你之後，憑手環進出，不用每次對名字。

**延伸：token 洩漏怎麼辦？**：可以撤銷（刪除 token 紀錄），也能限制權限範圍。

## 6. 為什麼要寫自動化測試？現在 79 項在測什麼？

**一句話**：測試是「每次改完程式自動重跑一遍的驗收清單」，改 A 弄壞 B 會立刻被抓到。

**比喻**：工廠出貨前的品管檢查表，而且是機器人自動檢查，3 秒跑完 79 項。

**內容**：登入權限、商品/客戶/訂單 CRUD、庫存不足擋單、狀態機規則、API token、角色權限、CSV 匯出、儀表板數據。

**延伸：什麼是 CI？**：GitHub Actions 會在每次 push 自動跑全部測試，紅燈就不合併——就算我忘了跑，機器人也不會忘。

## 7. 為什麼要用 Docker？

**一句話**：把「PHP 版本＋擴充＋MySQL」整組環境打包，同事拉下來 `docker compose up` 就跟我的環境一模一樣，消滅「我電腦上可以跑啊」。

**比喻**：泡麵附湯包——不用自己調味，每碗味道都一樣。

## 8. 正式站的部署架構是什麼？

**一句話**：Linux VPS 上跑 nginx（接待請求）→ PHP-FPM（執行 Laravel）→ MySQL（存資料），HTTPS 用 Let's Encrypt 免費憑證自動續期，UFW 防火牆只開 22/80/443，fail2ban 自動封鎖暴力破解 IP。

**比喻**：nginx 是櫃檯，PHP-FPM 是廚房，MySQL 是倉庫；HTTPS 是信封（路上沒人能偷看內容），防火牆是只開正門的圍牆。

## 9. CSV 匯出為什麼要加 UTF-8 BOM？為什麼用串流？

**一句話**：BOM 是檔案開頭的三個記號位元組，Excel 看到才知道用 UTF-8 讀，中文才不會變亂碼；串流是一邊查一邊吐資料，十萬筆訂單也不會把記憶體吃爆。

**比喻**：BOM 像包裹上的「此面朝上」貼紙；串流像水管直接接到杯子，而不是先把整桶水搬過來。

**延伸：匯出跟列表結果會不會不一致？**：兩邊共用同一個 `filteredOrders()` 查詢方法，篩選條件永遠同步。

## 10. 儀表板圖表的資料為什麼要「補 0」？

**一句話**：SQL 只回傳「有訂單的日期」，沒訂單的日期會消失，折線圖的時間軸就會歪掉，所以程式把缺的日期補上 0。

**比喻**：班級點名表——沒來的也要記「缺席」，不能直接從名單上消失，不然人數會對不上。

## 11. AI-First 工作流實際上怎麼運作？

**一句話**：需求拆解與驗收由我主導，AI 產生程式初稿，我逐檔審查、要求補測試、實際跑過驗證才上線。

**具體流程**：
1. 我把需求拆成小任務、决定做法（例如「匯出要跟列表共用篩選」）
2. AI 產生初稿
3. 我審查每個檔案的修改，不懂的地方要求 AI 解釋到我懂
4. 跑完整測試套件（目前 79 項），紅燈就修
5. 綠燈才 commit，CI 再驗一次，然後部署正式站驗收

**延伸：AI 寫的程式你負得了責嗎？**：品質靠三道防線——我的審查、自動化測試、CI。AI 是產能放大器，驗收標準和責任在我。
