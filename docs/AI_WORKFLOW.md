# AI-First 開發流程

本專案的所有功能均依循以下流程開發：AI 負責產出初稿與加速實作，人工負責需求判斷、程式碼審查與品質把關，最後以自動化測試驗證成果。AI 是加速器，品質責任始終在工程師身上。

## 流程總覽

```
需求拆解 → AI 產生初稿 → 人工審查 → 測試驗證 → 修正 → Commit
   ↑                                              │
   └──────────────── 下一個任務 ←──────────────────┘
```

## 1. 需求拆解

- 將大需求拆成可獨立完成、可獨立驗證的小任務（例如：「第一階段只做專案骨架，不做 CRUD」）。
- 明確定義每個任務的完成條件（Definition of Done），例如「migration 可執行」「測試通過」。
- 明確列出限制條件（不提交 .env、不放真實資料、頁面文字使用繁體中文等）。

## 2. AI 產生初稿

- 以明確的規格提示 AI 產出程式碼：指定框架版本、技術選型（Breeze Blade、Bootstrap 5）、命名慣例與檔案位置。
- 一次只讓 AI 處理一個區塊（例如先導覽列、再儀表板），避免大範圍生成難以審查。
- AI 產出的內容包含：程式碼、設定檔、測試與文件。

## 3. 人工審查

- 逐檔檢視 AI 產出的程式碼：命名是否一致、是否符合 Laravel 慣例、有無多餘依賴或過度設計。
- 檢查安全性重點：認證與授權中介層、CSRF、SQL Injection（使用 Eloquent／Query Builder 參數綁定）、機敏資訊是否進入版本控制。
- 不理解的程式碼不合併：要求 AI 解釋，或改寫為更簡單的版本。

## 4. 測試驗證

- 每個區塊完成後實際執行 `php artisan migrate` 與 `php artisan test`，不以「看起來正確」代替執行結果。
- 新功能需附對應的 Feature 測試（例如：未登入者不能進入儀表板）。
- CI（GitHub Actions）在每次 push 時重複相同驗證，確保結果可重現。

## 5. 修正

- 測試失敗或審查發現問題時，將錯誤訊息與期望行為回饋給 AI 修正，或直接人工修改。
- 修正後重新執行測試，直到全部通過。

## 6. Commit

- 測試通過後才 commit；一個 commit 對應一個完整、可運作的變更。
- Commit 訊息說明「做了什麼、為什麼」，方便回溯與審查。
- `.env`、真實密碼與機敏資料永不進入版本控制。

## 第一階段實例

| 步驟 | 實際做法 |
|------|----------|
| 需求拆解 | 只做骨架：Breeze 登入、儀表板、導覽列、placeholder 頁、Docker、CI、測試、文件 |
| AI 產生初稿 | 以 Laravel 13 + Breeze Blade 建立專案，將 Tailwind 介面改寫為 Bootstrap 5 繁中介面 |
| 人工審查 | 檢視路由中介層（auth）、元件命名、.gitignore 與 .env.example 是否含機敏資料 |
| 測試驗證 | 實際執行 migration 與 PHPUnit（含未登入／已登入儀表板存取測試） |
| 修正 | 依測試結果修正後重跑，直到全數通過 |
| Commit | 初始化 Git repository，以通過測試的狀態建立第一個 commit |
